# 全项目审查修复与上线说明

本轮按审查报告编号修复 1–4、7–10、12–14；问题 6 实现总开关和免打扰，其余标为实验性设置。问题 5、11 保留，详见根目录 `待修复.md`。

## 改动

- iOS 全局提示改用系统 Alert，避免与表单原生 Modal 竞争；管理员报名详情/编辑共享一个原生 Modal。
- 账户资料请求使用身份及请求序号隔离；旧账户的迟到响应不再恢复资料或权限。
- 退出解绑当前推送设备，离线待解绑记录保留到联网重试；游客注册不再保留旧账号归属。
- 资料 RLS 收窄为本人读取；管理员继续使用带权限检查的管理 RPC。
- 通知总开关与免打扰按设备同步，手动、定时活动及微信文章推送统一筛选收件人。免打扰为罗马 22:00–08:00，不新增服务器轮询定时任务。
- 自习室移除随机余座；首页/工具页汇率移除固定默认值；天气无数据不再显示晴天；实时请求区分无数据和网络异常，并覆盖响应体超时。
- 火车不再默认估算“三小时后到达”、补入写死的境外时刻，或把另一运行日的旧时刻平移成所选日期的数据；来源缺失或日期不匹配时显示无数据。
- 空教室按罗马日期查询，刷新/前台/分钟推进更新当前时段，跨日重载。公交、火车、文章与管理页面的时间统一按罗马解释或展示。
- 手册未保存拦截覆盖系统返回及侧滑；文章管理每页 100 条并有翻页按钮及稳定排序。
- 管理员报名写入成功后刷新失败，明确提示已保存，不误报保存失败。
- 首页“查看全部”改走独立页面，避免跳向 iOS 未注册的隐藏标签页。

## 必须执行的部署

本轮没有修改线上数据库，没有部署、发送推送或 push。版本号未递增。

1. 在 Supabase SQL Editor 完整执行 `supabase/migrations/044_app_privacy_push_controls.sql`（在 043 后）。可重复执行；不删除报名、账户、文章或推送设备记录。
2. 在仓库根目录，对已链接的正确 Supabase 项目执行：

```powershell
supabase functions deploy wechat-sync
supabase functions deploy wechat-webhook
supabase functions deploy wechat-import
supabase functions deploy event-registration-start-notifications
```

3. 更新客户端后验证通知设置；管理员客户端也应更新，否则旧版直接群发路径可能不遵守新开关。

微信采集、文章保存和现有定时计划不变，只调整通知收件人筛选。无需重新创建采集任务或活动定时任务。
