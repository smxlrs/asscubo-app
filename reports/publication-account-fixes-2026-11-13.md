# 文章、通知与账号注销修复（2026-11-13）

## 行为变更

- 网站继续负责文章内容；App 管理员可独立隐藏文章。新增 admin_hidden，不再用单一 is_published 同时表示网站状态与人工决定。旧 App 的软删除也由触发器兼容。
- 移除历史文章清理入口。数据库同时阻止物理删除带 wordpress_post_id 的记录，避免旧版清理按钮清掉去重身份、造成重新导入和重复推送。隐藏与恢复不改网站，不改 notifications 表。
- 同步预览和结果的可见数量扣除管理员隐藏记录；隐藏文章仍可更新内容，但不会重新发布或重复推送。
- 网站新文章推送包含文章 ID 和链接；新手动通知保存后取得实际 ID 再发送，明确携带 notificationId，并保留 articleId 回退以兼容旧 App。
- 通知点击统一处理：运行期监听与冷启动恢复共用去重队列，导航与登录初始化完成后跳转，并清理已处理的系统通知响应。非点击动作不导航。
- 文章页与动态通知页使用 publication_feed 服务端搜索、排序及分页。文章/通知合并后按置顶、日期、ID 排序再分页，避免旧置顶漏取；动态分类兼容文章分类别名。
- 搜索输入防抖，筛选/账号变化时清空旧结果并隔离在途请求；加载更多只允许单个请求，双来源按 type:id 去重。
- 新查询函数使用 SECURITY INVOKER，保留现有 RLS，并显式排除其他用户的定向通知。文章页只读 articles，动态页可合并通知。
- 账号注销由服务器校验 Supabase 邮件重认证 nonce：SHA-224(email + nonce)、10 分钟有效、每账号 15 分钟最多 5 次失败。失败计数返回 false 并提交，不能因异常回滚而绕过；重新发码不重置失败预算。
- 校验与账号删除在同一行锁事务执行，沿用既有报名释放名额和级联触发器。原无验证码接口已撤销客户端执行权限。客户端不再使用 Auth 不支持的 verifyOtp(type: 'reauthentication')。
- 注销验证码说明已同步简繁英意四语。
